# 运行机制

本页说明 SkillX 在插件中怎样被提取、启用、执行和优化，以及为什么启用 skillx 能减少耗时和 Token。

## 开发者使用路径

```text
完成一次代表性任务
→ 从会话菜单发起 SkillX 提取
→ 等待提取 Agent 生成候选
→ 在 SkillX 页面查看能力
→ 按需启用或停用
→ 后续任务由模型发现并调用 SkillX
→ 用新的执行会话优化能力
```

首次任务仍由 Agent 正常探索。只有当任务结构稳定、执行证据完整时，才适合提取为 SkillX。

## 证据怎样被提取

插件读取 DSH 会话事件，而不是只读聊天文本。证据包括：

| 证据 | 用途 |
|---|---|
| 用户消息和助手回复 | 还原任务目标、输入来源和输出要求 |
| 工具调用和结果 | 还原实际操作、参数、状态和失败点 |
| 未完成调用 | 判断中断或异常边界 |
| step 事件和用量 | 比较耗时、模型调用和 Token |
| turn 结束原因 | 判断会话是否完整完成 |
| 模型请求配置 | 后续提取或优化沿用来源会话模型 |

提取 Agent 必须把历史内容当作证据，而不是当作新指令。它要从证据中总结可复用输入、必要工具、验证条件和失败边界。

## SkillX 怎样运转

启用 skillx 后，模型侧流程变短：

```text
发现能力名称和说明
→ 读取输入输出契约
→ 准备 JSON 输入
→ 调用 capability_run
→ 使用输出和回执
```

插件内部流程保持完整：

```text
加载能力版本
→ 加载依赖闭包
→ 校验输入
→ 运行执行程序
→ 调用工具或依赖能力
→ 记录事件
→ 校验输出
→ 返回结果
```

外层模型读取公开契约，执行程序负责消费中间工具结果。这个分工是效率提升的主要来源。

## 执行程序怎样使用工具

执行程序可以调用 DSH 工具，例如 shell、文件、浏览器或其他已注册工具。调用经过宿主：

- 保留原 Agent、root call 和 execution token。
- 使用当前会话的沙箱策略。
- 工具调用事件写入执行记录。
- 失败会被记录为内部问题、外部阻塞或未知问题。

执行程序也可以调用声明过版本锁的其他 SkillX。这样可以把大任务拆成几个稳定能力，但外层模型仍只看到当前能力的公开契约。

## 恢复怎样工作

恢复分为前台恢复和后台维护。

前台恢复发生在同一次 `capability_run` 内。它读取当前输入、程序、执行轨迹和失败信息，在当前权限和证据范围内补全一个经过 Schema 校验的结果。

后台维护发生在前台失败或超时时。它分析证据、生成诊断，再启动优化任务修订能力定义。

## 为什么启用 skillx 更快

效率提升来自少做重复工作：

| 成本来源 | 未启用 skillx | 启用 skillx |
|---|---|---|
| 能力理解 | 模型读取 Skill 说明和上下文，自行判断步骤 | 模型只读契约 |
| 计划生成 | 每轮重新规划工具顺序和参数 | 已验证步骤在执行程序里固定 |
| 中间状态解释 | 每个工具结果都回到模型上下文继续推理 | 程序内部消费工具结果 |
| 失败定位 | 调用方继续排查 | 插件保留执行记录并分类恢复 |
| 版本复用 | 依赖聊天记录和临时判断 | 依赖不可变版本和回执 |

## 测试效果

三轮对照测试任务为：本地 commit、创建模拟 MR、合并 MR、回读核验。

| 指标 | 未启用 skillx | 启用 skillx | 变化 |
|---|---:|---:|---:|
| 平均耗时 | 74.583 秒 | 51.381 秒 | 减少 31.11% |
| 平均会话 Token | 244,280 | 139,644 | 减少 42.83% |
| 平均模型调用 | 10.333 次 | 6.333 次 | 减少 38.71% |

完整归档见 [测试结果](tests/2026-10-14/README.md)。这组数据是小样本描述性结果，不代表所有任务都有相同比例收益；它能说明该类固定、多工具、可验证任务适合启用 skillx。
