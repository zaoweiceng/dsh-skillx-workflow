# 调用开销：公开契约承担封装责任

## 2026-10-23 框架修订

后续工作仅修改框架，未修订已生成的 SkillX/workflow。以下实现替代仅针对明确能力名的预载方案：

| 问题位置 | 原因 | 最小框架修改 |
| --- | --- | --- |
| native-skills.js / index.js | 目录只有说明，调用工具的 input 又是任意 JSON；普通任务必须先消耗一轮读取契约 | 在既有原生调用工具中呈现根能力的输入类型及用途，由模型自动选择；大型目录继续渐进加载 |
| native-skills.js | 模型加载 UI 标签、示例和内部探测配置，且重复读取已知接口 | 仅压缩呈现注释，保留全部输入约束、默认语义和兼容前提；不改变存储或业务参数 |
| extraction-requirements.js / native-agent.js | 类型规则要求 workflow 必须有能力依赖、skill 不得依赖能力，促使为分类拆出额外包装层 | 删除这两条普遍规则及相应作者指令；保留显式场景要求、来源职责和真实依赖校验 |
| result-delivery.js / index.js | 只能先返回整体结果，超限后再逐页读取；没有执行前声明所需结果字段的接口 | 增加 select 指针投影；完整结果仍校验、保存，投影仅控制返回内容，原始业务状态继续保留 |

这不能证明已有生成物的必填参数数量已经合理，也不会由框架猜测哪些参数可推导。当前修改没有自动合并已发布能力、修改资源程序、修改存量 Schema 或调整恢复策略。真实的参数组织仍须由 Agent 按来源重新提取，不能通过观察者手工改产物来证明框架有效。

本次未新增或运行单元测试，已检查修改文件的 JavaScript 语法和 diff，并确认隔离服务启动、原生运行接口返回 200。此前指定能力名的实跑只验证已撤换的预载方式，不能证明本次普通任务发现路径的 Token/耗时收益；两项业务失败亦不得从成本证据中删除。普通任务自主选择和完整成本对照仍待独立实跑，不能宣称已达到整体节省目标。

## 根因证据

2026-10-23 的三次旧开启实跑，模型响应分别 3/7/5 轮；原程序均为 2 轮。第三次完整 Token 为 125160，五轮分别 21155、24189、24900、27029、27887。重复计入历史上下文属于真实请求成本，不是只统计新生成文本。该轮有 8 次结果读取，分两轮执行。

根输入要求调用者重复四份数据集路径、派生输出位置及子能力配置；根输出直接嵌套全部子结果，摘要没有承担聚合职责。宿主的有限预览无法从任意 JSON 推断业务重要性，截断后导致更多模型往返。根成功执行本身约 8 秒，不足以解释完整 32–96 秒。

## 最小修复

1. 修订入口不再强制冻结有缺陷的 Schema。默认保持接口；用户明确选择升级时允许原生作者修改真实输入/输出 Schema 和实现，同步版本。升级不是运行时适配旧调用。
2. 根能力的输入以用户变化维度为边界。由程序派生可确定的路径、重复子参数；环境选项保持明确，禁止静默选择另一环境。目录约定和默认值必须有来源证据，程序实际实现，不能只写 Schema 注释。
3. 根返回明确的业务结果，含全部要求的汇总、检查结果、失败及报告位置；详细分支证据写入完整报告。不把任意层级的子输出原样递归透传，也不靠宿主猜测重要字段。
4. 原生作者自主修订实际能力。宿主不手写本例业务程序、不扩大预览预算、不修改恢复、不用原程序回退。不引入 profile 映射或新一层契约代理。
