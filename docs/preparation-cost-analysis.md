最明显的无效循环是诊断会话 `4d66572a-dc7c-47e6-9418-2bed7b7a44a9`：Agent 把要求的 JSON 对象编码成字符串，旧校验只返回泛化错误。首次拒绝后，步骤 4–19 继续提交同类非法结构，消耗 743,077 tokens；不能将整个会话的 848,517 tokens 都称为浪费。当前已明确输出类型并返回有限字段路径/约束反馈，之后完整诊断成功，因此本次不再为旧循环增加新的重试或熔断机制。

剩余 1,923,392 tokens 也不是理论最小必要成本：包括正常推理、实验和验证。High 推理和较大输出会消耗时间与 tokens，但用户要求配置与来源/调用方一致，因此不降低模型、推理档位或 maxTokens，也不延长预算掩盖问题。

## 本次仍有证据的两项最小调整

1. **完整目标只提供一次。** 优化初始上下文已经包含 `selectedCapability` 的正文、实现、契约和版本，但确认复用仍要求再调用读取工具。现在把这份完整输入登记为已提供；再次请求相同版本只返回引用。其他依赖仍按需读取，最新版本检查和发布冲突检查不变，过时版本不能据此通过验证。
2. **成功恢复记录不作为重复来源再传一遍。** 后台诊断必须读齐包含 `recoveredEvidence` 及摘要的所有页，成功提交并持久化之后才启动作者。该诊断会话已原样保存全部恢复记录，再加入原恢复会话作为第二来源会重复传输并强制重复阅读。现在作者只读取这份完整的诊断会话；来源模型仍继承诊断，而诊断配置继承原调用方。不是用诊断摘要替代原始证据。

不修改 DSH Agent 生成的业务程序、能力版本或审批边界。内部恢复和后台维护生命周期不变。没有引入自动重试，没有对所有工具结果做危险裁剪，没有声称本次调整已实测节省某个 token 百分比。

## 验证与边界

- 现有 19 项测试通过；优化复用测试覆盖初始完整定义的引用、无重复发布，原有按需读取测试仍要求未提供的能力先读取。
- 独立审查确认完整证据读取、正常结束、持久化与模型继承链不被绕过；版本变更不能复用过时定义。
- 本次不追加昂贵的真实 LLM 提取实验；历史 576 万不能作为本次修改后的新成本预测。
- 已完成的 v7 正式实验三轮没有恢复/后台学习，平均调用耗时 48.164 秒、140,700 tokens，对照 81.238 秒、281,586 tokens。它证明运行期节省，不能替代提取期的成本测量。
- 后续若出现新缺陷，按会话分别观察有效输入、输出、重复失败和后台成本；只有再次出现可复现无效循环，才有依据追加通用机制调整。
