# 提取与失败反馈复核

日期：2026-10-16。仅观察原生流程、进行只读功能调用与代码审查；本轮没有新增、修改或运行开发测试。此前已有的测试改动保留，后续需同步新协议的 fixture 与覆盖。

## 实际结果

从空目录重新提取同一份 38 行、63,784 字节的服务重启对话。来源始终为同一 JSONL 摘要；每轮运行前冻结代码，运行中不修改参数、契约或业务程序。所有业务实现及修订均由原生模型提交。

最终保留一个独立的 `process-ancestry-check`，输入要求显式提供起始 PID 与目标 PID。结果区分可信判定、观察不完整与操作失败；未命中必须有完整观察依据，正向命中可以由已观察到的路径证实。链不包含 PID 1；不据 PPID 1 推断孤儿化、监督状态或重启安全。

最终冻结 22 个基础用例，加上通用故障注入共 77 项，全部通过。没有生成 workflow：来源中重启最终结果未确认，模拟器也不能验证生成的守护脚本存活与实际重启，因此相关候选被撤回。没有为了数量补充包装。本轮未触发已发布 workflow 的依赖复用链，不能将静态支持宣称为实测通过。

真实只读调用受到当前 DSH 沙箱的 `ps` 权限限制，返回明确业务错误，没有误报为未命中，也没有改变权限。外层执行完成不等于业务查询成功；本轮没有验证获准环境中的真实成功查询。

主要耗时是模型长输出，以及小格式错误导致整套契约重新提交；不是一直在执行工具。v6 模型累计输出约 11.9 万 tokens，最终复核约 12.8 万。累计 tokens 含多轮上下文，不等于单次上下文大小。初始请求仅传文件描述、计划与必要契约；证据通过有界索引、记录及片段读取，未内联来源全文。运行预算按证据规模与阶段数计算，默认没有步数上限；延长预算能避免过早中断，但不能消除协议往返。

## 本轮修正的通用机制

- 契约冻结前检查完成结果与失败覆盖的矛盾；可信空结果、否定结果也受故障门禁约束。
- 默认、空结果与边界中的必要调用参与故障注入，覆盖非零退出、保留部分输出、截断及超时。
- 根字符串输入需要安全边界覆盖；测试业务函数不能读取私有 fixture、cursor 或 trace。
- 工具响应返回具体分支字段诊断；提交参数显式声明数组，覆盖错误列出实际与预期名称。
- 原生非法 JSON 提交允许模型做一次受限格式修复，保留原文与原截止时间；不替模型修参数、不重放业务动作。
- 机器执行结果作为 control 证据保留，压缩与完整 reasoning 块排除；补充纯工具会话不覆盖主来源模型配置。
- 运行后审查意见以诊断假设输入，模型独立核实；选择复用原实现也必须通过本轮冻结契约。
- 删除检查所有现存引用（含停用条目），返回引用者；发布与删除共享写队列，读取及优化核对不可变修订 ID。正常执行绑定依赖快照，历史审计保留。
- 执行页面通过宿主重命名接口保存标题，避免写入无法重放的会话事件。

模型仍可能设计出语义不足的 oracle，模拟通过不能替代外部真实性证明。剩余验证包括获准环境的真实查询、依赖拒删与并发场景、格式修复触发路径及开发测试；本轮没有为覆盖这些场景构造新开发夹具。下一项性能优化可考虑冻结前的契约增量修订，避免一个字段错误触发整套重写。
