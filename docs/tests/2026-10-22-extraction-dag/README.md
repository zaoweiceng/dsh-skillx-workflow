本轮只调整提取与展示投影；没有新增执行器恢复、并发或权限语义。

- 计划从职责条目派生省略的依赖列表；旧显式列表仍要求一致。
- 未验证规划草稿可以恢复；来源变化、摘要冲突、校验未通过仍拒绝发布。
- 图从程序语法与锁定版本的子工作流生成，不使用 Agent 编写的图或阶段注释。动态区间明确显示未知。
- 回归：全量 92 项通过（含动态区间潜在调用展示、异常分支、不伪造成功汇合、带 useDraft 的草稿修订、摘要冲突与语法门禁）。真实 DSH PTC/子进程 14 项通过。

隔离验收在专用 DSH 3081 与只读根文件系统容器中进行，数据与输出均为合成测试材料。正常 3080 服务未重启。Agent 自主完成原始任务、提取、执行与修复，观察者不改其业务产物。

成本分别报告原始任务准备、提取及修复、三对独立会话的热调用。Token 使用供应商报告的非缓存输入、缓存输入和输出之和；包括失败响应，不以纯脚本耗时或三个调用均分一次会话 Token 代替完整会话成本。成本不含观察者开发代码、检查日志与人工等待的开销；提取及调用 Agent 的失败响应均计入。

## 本轮真实观测

- 原始业务由 Agent 自主编写与修复，7 项验证通过；独立核验确认真实三分支时间重叠、产物损坏后只重做受影响分支、顶层失败不残留成功报告、CLI 安装中断时已有包文件落盘。
- 原始任务准备共 26 次模型响应，2,524,026 Token，活动轮次耗时 608.735 秒；含观察者反馈间隔的墙钟为 784.205 秒。不能把它当作单次热调用。
- 第一轮提取失败，未发布：规划只保留一个 workflow，构建要求调用方提供业务源码，未达三层嵌套验收；覆盖片段门禁拒绝了省略号及非原文证明。Agent 随后将 useDraft 与 draftEdits 同时提交，旧接口拒绝组合，未应用修正。保留这次失败成本，不能从最终统计删除。
- 已修正提取提交组合语义，保留摘要、语法与覆盖检查，并澄清职责判断和业务实现归属。第二轮仍从同一来源自主提取，观察者不编辑候选或计划。

- 第二轮静态提交通过，产出 2 个 SkillX、3 个 workflow；真实调用前，调用 Agent 根据公开契约识别出容器执行目标丢失，拒绝在宿主运行，未调用 capability_run。该轮不能计为执行验收成功。产物已移至测试环境回收站，历史快照、提取和调用证据保留。
- 自动图从第二轮产物解析出 36 个节点、35 条边，包含三种嵌套 workflow。17 条虚线为动态区间中的潜在调用关系，不能据此声称并行、调用次数或实际成功汇合。无图元数据由提取 Agent 编写。
- 第三轮补充了保留容器/远端/解释器执行目标的通用提取规则；仍由 Agent 自主决定拆分和实现，未强制命名或手工编写业务产物。

## 验收结论与剩余问题

- 已完成：提取计划依赖派生、失败规划草稿恢复、摘要冲突检查、同次提交草稿修订及完整校验、自动程序图投影与界面。旧接口及验证门禁保留。本轮未新增运行时恢复或执行器并发语义。
- 尚未通过：稳定自主提取至少三层 workflow 并在指定容器内正确执行完整故障验收。第二轮虽然结构达到三层，但环境契约缺失；第三轮仍退化为单个 workflow，且没有容器运行入口。
- 自动图能够展开锁定的潜在调用，但复杂动态控制流仅展示明确标注的未知区间和虚线包含关系；它不是实际运行轨迹，也不能证明真实并行和成功汇合。
- 原始程序的 CLI 并发/中断恢复、复杂 Python/JS 依赖、故障分类及局部重做验证已通过；这些结果不能转移为提取产物的验证结果。
- 静态发布仍不能保证提取产物可在目标环境使用。此次由调用 Agent 识别隔离契约不足并回退/阻塞，尚未形成可靠的机器验收门禁。
- 继续反复扩充提示词不足以解决已观察到的粒度漂移和执行目标丢失。后续应优先让来源中的独立结果与执行边界成为明确的提取验收条件；不宜用运行时修补、强制凑节点或削弱门禁掩盖这些缺陷。

第二轮产物保留在隔离测试回收站；第三轮产物已停用。测试证据与成本原始记录保留在 `~/.cache/skillx-labs/bix3t7zl/evidence/dag-v2/`。

收尾：额外的 baseline 3082 服务已关闭，专用测试容器恢复为 exited；隔离 3081 页面保留供审阅，正常 3080 未重启。全部准备、提取、预检和 6 次热调用的活动耗时合计为 3,095.346 秒，完整 Token 为 19,973,995，模型响应数为 274。这是包含失败的实验总成本，不是成功工作流的复用成本。
