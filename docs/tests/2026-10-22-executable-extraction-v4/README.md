# P0 可执行提取：隔离实跑记录

状态：2026-10-23 完成本轮隔离实跑与三组执行阶段对比。核心调用链通过；没有获得性能收益，仍有下述错误分类和安装锁边界。

## 范围与方法

本轮不引入 Wasm，不修改运行时恢复策略，不新增或运行单元测试。通过隔离 DSH 的原生 Agent 自主提取、调用与修订；观察者修改宿主接口、核对真实产物并提供失败事实，没有手写提取出的业务实现。正常 3080 实例未重启；业务运行在专用 Linux ARM64 Docker 容器。依赖为 Node 22、Python 3.11、pandas 2.2.3、numpy 2.0.2、pyarrow 19.0.1、sharp 0.34.3、ajv 8.17.1、esbuild 0.25.10。所有数据为本地合成 fixture。

方案见 [设计](../../design/executable-extraction-v4.md)。宿主改动包括：提取用途结构条件、Docker 目标的可执行绑定与子调用继承、资源传输、同批版本锁、草稿提交幂等处理、按程序调度受管理进程，以及作者对现有资源正文的只读访问。DAG 从实现及锁定依赖生成，不要求作者另写图。

## 实跑发现并修订的缺陷

1. 同批新旧版本混淆造成静态提交失败；宿主分配新版本并原子锁定依赖。
2. Docker 边界只是说明文本，宿主无法按目标执行；现在有公开目标输入、目标内资源与依赖执行及预检。
3. 编排 Promise.all 被进程排队串行化；受管理进程遵循程序控制流，不再让叶子重复声明并行字段。
4. 图像尺寸和 CSV 活动行金额错误、JS 语法错误误分类，由原生作者根据失败证据修订。
5. CSV 宣称 reused 却重写 Parquet；增加可验证的缓存身份并实跑比较 hash/mtime。
6. 作者只能获得资源摘要，又无法在首份草稿前读取资源正文；只读工具支持精确 JSON Pointer，且草稿读取可回到选中修订。
7. CSV Parquet 从源流程的活动行分组摘要变成明细，且丢失唯一 ID、严格类型和 manifest 行数校验。正常样本 passed 没有暴露问题；独立读取 Parquet 和真实错误输入调用识别了缺陷。该阶段的三组性能记录作废，不代表等价执行比较。

## 性能统计口径

同一 traex / gpt-5.5 / medium，双方均新建会话、预热依赖、全新输出目录、force=true。关闭侧调用现有原程序的 run-release；开启侧只允许 capability_run，禁止回退原程序。关闭侧已经是可复用脚本，不能把它表述为每次从零手工推理执行。

Token 取完整 zstd 多帧会话中的全部 assistant/message 与 assistant/attempt usage，每条只计一次，包含缓存输入、非缓存输入与输出；若有恢复子会话也纳入。耗时为用户输入后 turn/start 到 turn/end 的完整活动时间，包括工具、模型、失败和重试，排除两次人工发起间隔。提取、修订、依赖准备和故障演练均排除在本表之外。原始日志与参数留在本机隔离 evidence/dag-v4，不复制私有对话到仓库。

## 边界

已实跑的是 macOS 宿主到 Linux 容器；没有验证 Windows 宿主、Windows 容器或 SSH。默认提取目标仍为 local，Docker 来源需要明确选择。目标绑定不是完整对抗性沙箱。宿主 Docker 客户端退出不保证远端瞬时取消，目标内执行有独立超时；本次中断是在容器内精确终止安装进程。

静态 DAG 对动态循环/异常控制区间明确标为未知，虚线是包含关系，不冒充执行顺序。三层实际调用和叶子并行由执行回执与时间区间证明。结构校验和编译通过都不等于业务正确；这轮真实验收实际拦下了产物语义和输入校验丢失。

## 剩余问题与展示

第 2 组发现输入文件不存在时分类仍不统一：CSV 为 input_invalid，SVG 为 environment_missing_dependency，模块为一般 failed。故“缺 pandas vs 错误 JS”两类已区分，不代表所有环境/输入/代码错误均已正确分类。该缺口保留为后续修复项，没有用运行时兜底掩盖。

DAG 识别受 Schema 约束的字符串同步操作及未遮蔽的内置同步谓词，避免参数验证将后续 Promise.all 整段遮蔽；有绑定重写/动态控制时仍保守处理。真实提取的数据集程序自动生成 12 个图节点，包含三路并行与汇合，浏览器已核验。图展示在全宽区域，避免三路分支被半宽表单挤出视野。原始截图：evidence/dag-v4/automatic-dag.png。批次循环仍为动态区间，执行次数以真实回执为准。
