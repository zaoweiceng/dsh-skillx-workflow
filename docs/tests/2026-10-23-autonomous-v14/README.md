# 隔离调用验证（2026-10-23）

**结论：本轮未达到降低调用开销的目标，开启侧验收失败，不能作为优化成功交付。**

本记录只描述本地合成任务，不是公开性能基准。任务是双批次、每批 training/holdout 的发布审计：CSV/Parquet、SVG/PNG、JS 打包加载并行后汇合，另外执行批次恢复、分支恢复、真实产物损坏、失败传播、依赖缺失、脚本逻辑错误、CLI 并发安装及中断恢复。

## 条件与成本口径

- 两侧均为 TraeX / GPT-5.5 / medium，相同输入与固定 Linux ARM64 容器镜像，原始输入和工具脚本只读，输出、缓存、安装前缀均隔离。
- 开启侧最初使用普通任务描述，不提供能力名。生成和修订均由原生只读作者完成；观察者没有修改已发布 SkillX/workflow。
- 排除初次提取；包括所有执行尝试、原生修订、失败请求结算及后续验收反馈。Token = inputTokens + cacheReadTokens + outputTokens；不使用仅统计成功主会话的 UI 数字。
- 耗时采用主任务开始至最终相关修订/执行结束的完整墙钟时间，包含排查及宿主更新间隔。成功后不重新开始计时。中途独立验收发现假成功，反馈后继续同一轮，因此不能把本轮说成无人监督的一次成功调用。
- 对比仅保留一组正式配对；此前旧框架的诊断尝试单独留档，不充当性能改善证据。

## 已确认的框架问题与修改

1. 连续作者会话曾被每步重建，接口规划没有直接进入构建草稿。保留原生连续历史，草稿继承规划的公开 Schema。
2. 源资源到最终提交才复制，使草稿阶段无法局部编辑原脚本。改为保存草稿时复制；允许精确读取所选源码工作区内的辅助文件。原 CLI 可通过资源 argv 接口执行，保留原有 JSON main 接口。
3. JSON 边界把可选 undefined 当成异常；并行异常以错误码作为唯一键，导致同码异常覆盖。使用 JSON 序列化边界，每个异常单独标识，保留真实能力身份及 Schema 问题。
4. 结果预览把省略对象改成 null、把路径截成半截，误导调用者继续修订/执行。改为 `$omitted` 标记，直接指向同一 runId 的保留结果；未新增结果校验哈希。
5. 局部修订强制完整读取所有历史终端结果，随着重复编排不断放大成本。修订只需选择相关证据；初次提取的目标、结果与规划引用要求保留。
6. 普通 capability_run 不再允许恢复 Agent 代行业务或在调用外补写成功结果。程序缺陷通过显式只读修订后重新调用，业务恢复必须由 workflow 实现。
7. 局部修订虽然保留已发布依赖锁，仍因未重新读完整依赖而被泛化错误阻断；重复同一错误后退出。修复为复用当前 version/revision 都未变化的依赖锁，并在变化时报告具体依赖。另移除代码中存在的累计提交次数上限；它不是本次该失败的实际触发原因。
8. 普通调用明确请求 600,000 ms，但内部仍用 Math.min(120000, timeoutMs) 截为 120 秒，触发提前超时和整条重跑。现透传已有请求预算，接口上限不变。实际超时账本是约 120 秒，不是 Agent 声称的 600 秒；约 121 秒是并行进程时长之和，不能据此推算 480 秒宿主差额。

## 独立核验

- 新提取图有 9 个能力，包含至少三层实际 workflow 嵌套、三分支并行与汇合。仅有图和 passed 标签不足以通过验收。
- 首次 Agent 报告完成时，4 个承诺的归档文件都不存在，且多项故障只有占位 passed。该结果被拒绝，成本保留。
- 初版数据集 workflow 无条件调用三个分支，resumePolicy 仅回填为输出标签；批次也无条件重跑。初版损坏验收以请求式失败代替真实损坏，不能视为通过。
- 新返回格式用本轮真实保留输出回放：49 个省略指针均可解析，预览约 7.5 KB；随后已在原生调用中观察到 `$omitted`，取代旧的 null/半截路径。
- 原始 Python CLI 资源在隔离容器中使用原 argv `--help` 执行，退出码 0；没有改业务输入或发布生成物。
- 没有新增或运行单元测试。执行了 JS 语法检查、差异检查、文档本地链接检查及上述实跑。

## 剩余根因及边界

1. **公开参数没有完整继承下层约束。** 根的 coverage 是任意 string 数组，下层却采用固定值；根还把原脚本中已固定的 Python、Node、CLI 路径暴露为调用者必填字段。普通任务触发后重新发现路径、纠正覆盖参数，产生多次请求和失败。
2. **提取仍在重写稳定脚本中的判断。** 保存原脚本和 argv 的框架通道已打通，但自动作者仍重写了故障判断、状态映射、摘要复用。生成程序的结构正确并不证明语义等价。
3. **根与子流程重复拥有验收和复用判断。** 多层各自读旧摘要、判断证据、修改 status；子流程修复后上层仍可能接受旧失败/假成功，或用另一套条件否决真实成功。仅更新版本锁没有消除重复逻辑。

已修复的宿主超时、JSON 边界、并行错误身份、资源 CLI、预览和修订读取问题能消除具体框架故障，尚不足以解决上述提取语义问题。本轮没有用运行时自动恢复、手改生成物或新增通用门禁兜底，也没有继续增加未验证的编译器设计。
