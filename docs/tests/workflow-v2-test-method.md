# 工作流 v2：模拟 commit 与 MR 对照测试方法

记录日期：2026-10-15。对应 2026-10-14 已完成的 v2 实验；本文记录测试方法，不代表重新执行测试。

## 目标与范围

测量同一任务在禁用和启用现有工作流及配套 SkillX时的端到端耗时、模型 tokens、调用次数和成功率。任务是：检查隔离仓库的改动 → 本地提交一次 commit → 创建模拟 MR → 合并模拟 MR → 回读核验。

所有 Git 托管操作均由本地模拟服务完成，不添加真实 remote、不 push、不创建或合并真实 MR。模拟合并更新服务状态，真实本地 main 分支仍停留在基线；不能据此证明真实托管平台的集成兼容性。

本次只测已有 v2 的执行成本，提取与历史优化成本不计入六轮执行指标。工作流此前由 DSH 原生 Agent 生成；测试人员不编写、修改或修复业务工作流。

## 执行步骤

1. 保存测试前配置、能力开关、版本/hash、源码 hash、模型参数及 fixture 身份，创建独立证据目录。配置备份仅本机保存，归档不包含凭据。
2. 准备夹具。新目录才使用 `fixture.py setup`；已有夹具使用 `restore`。恢复前停止模拟服务，并确认路径确属测试仓库：恢复操作会重置仓库并清除未跟踪文件。
3. 依顺序选择 B 或 W，只在上轮前台与后台任务均终态后切换两项实验能力。其他 Skill、工具、模型和权限保持不变。
4. 将 fixture 恢复到相同 baseline、相同五个文件内容、空 MR 状态，再启动模拟服务。每轮开始核对 Git 状态和无 remote。
5. 在 3080 网页新建会话，设置相同工作目录与权限，发送下述完全相同的自然语言请求。不要提示工作流名称、执行脚本或步骤答案，也不预先替 Agent 读取 API 文档。
6. 提交后仅观察。业务错误由 DSH 原生 Agent 自行恢复；不追加消息、不改工作流、不重启服务来帮助当前任务、不以补跑替换失败。若终态失败，保留原始失败和费用。
7. 前台终态后运行独立 `fixture.py verify`，保存原始验证结果；等待可能存在的恢复、诊断、学习任务终态，收集其记录。必须先保存证据，再还原 fixture 进行下一轮。
8. 六轮结束后核对请求一致性、能力实际调用版本、源码 hash、usage 完整性、全部后台任务及六份验证结果。恢复本次修改的配置和开关、停止模拟服务、还原夹具，记录恢复证明。

## 成功判定

不能仅以 Agent 回复“完成”为成功。独立校验器同时核验：

- 只有一次符合任务要求的本地 commit，父提交为 baseline，提交信息固定。
- 已提交和工作区文件字节符合初始任务内容，变更集合恰好为五个文件，工作区干净。
- 没有新分支或 remote；真实本地 main 保持 baseline。
- 恰好一个模拟 MR，状态为 merged；sourceSha、mergedSha、模拟 targetHead 与提交 SHA 一致。
- 审计链完整，包含创建、合并以及成功读取 merged 状态的证据。

保存每轮 commit SHA、MR ID、状态、模拟合并 SHA、审计摘要和 verified 值。Agent 宣称成功但独立核验失败仍记为失败。

## 耗时、tokens 与调用次数口径

- **前台耗时**：原始用户请求接收时间至对应 `turn/end`，包括前台内部执行和同步恢复；以原生日志计算，不使用 UI 四舍五入显示值。夹具重置、人工准备及独立核验时间不计入。
- **前台 tokens**：汇总该任务原生会话已报告的模型 usage；如有内部推理或前台恢复，关联其子会话并去重纳入。receipt 用于关联，不能将 receipt 中的 usage 再加一次。
- **模型调用次数**：记录真实模型调用及尝试；不是工具调用次数。插件内部 dispatch 单独审计，不能因调用方只调用一次黑盒工具就当作内部没有执行。
- **后台成本**：诊断、修复和学习分别记录耗时、tokens、结果、版本变化。后台耗时不相加伪装成前台等待时间；后台 tokens 单列，避免遗漏或重复计算。
- **缺失用量**：无 usage 的标题生成、重试或缺失日志标记为未知，不能填零。本次六个辅助标题请求未返回 usage，表中不含该部分。
- **汇总**：每组按三次原始尝试计算均值、中位数、总调用和成功率，不排除失败或只选最佳。下降比例为 `(B组均值 - W组均值) / B组均值 × 100%`。记录缓存用量（如提供），不把 token 总数直接等同于费用。

交替顺序只减少顺序偏差；本实验没有控制服务端负载或缓存冷暖，各三轮只能提供描述性结果，不能证明统计显著性。

| 轮次 | B 耗时（秒） | B tokens | W v2 耗时（秒） | W tokens |
|---|---:|---:|---:|---:|
| 1 | 75.594 | 235,817 | 47.716 | 130,996 |
| 2 | 66.044 | 230,364 | 52.228 | 134,727 |
| 3 | 82.111 | 266,660 | 54.199 | 153,209 |
| 平均 | 74.583 | 244,280.333 | 51.381 | 139,644 |
