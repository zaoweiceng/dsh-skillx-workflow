# 调用契约收敛：隔离实跑

## 修改边界

宿主界面增加明确的“保持现有输入/输出接口”选项，默认保持；本次由用户授权取消，原生作者自主升级根能力至 v8（7224db2d-1650-4f17-bd9c-30793708dd0c）。未手写生成的业务程序、未调整预览字节阈值、未改运行时恢复，未编写或运行单元测试。

根能力从 releaseA/releaseB 各自提供重复 datasets，改为一次 datasets；内部派生两批 bundle/PNG 输出路径。根合并脚本返回明确的完整业务摘要，完整子结果保存到 release_audit.json 的 details.batches。失败报告同样保留详情。环境配置仍显式传入，不写死本机目录、容器名。

作者同时把两个独立批次的根调度从串行改为 Promise.all。因此耗时改善不能全部归因于结果摘要；模型轮数与结果读取次数是直接验证调用开销的指标。

## 开销根因

旧第三次结果实际 17729 字节，超过 16384 预览阈值。机械预览无法保证业务汇总完整，导致两轮共 8 次结果读取。五次模型响应总 Token 依次为 21155、24189、24900、27029、27887，合计 125160；最后两轮占 54916。统计含缓存输入和输出，不能当成 12 万字新输出或等价现金成本。

旧根调用参数第三次为 3433 UTF-8 字节；新第一轮为 1686 字节（均为紧凑 JSON 参数），减少约 50.9%。调用数据去重，但解释约束更明确，inputSchema 文本从 4253 增至 5005 字节，不能声称 Schema 本身缩短。新成功返回 2831 字节，减少约 84%，业务要求完整，不需要后续读取。

## 复验口径

同一 traex / gpt-5.5 / medium、预热依赖、新会话、新输出、force=true，中间 v8 采用三组交错 OFF→ON；发现失败并修订后，最终 v9 另跑三次 ON，与本轮同环境三次 OFF 对照，非同时交错。用户任务与上一轮相同，仅标签和输出目录改变。OFF 使用现有原程序一次公开命令；ON 必须通过 skill 加载当前公开契约并 capability_run，无原程序回退。统计完整 turn/start→turn/end 和每次模型 usage，包含失败与重试，排除提取/修订、准备及额外验收。

[设计依据](../../design/invocation-cost.md)。原始证据保存在本机隔离目录 ~/.cache/skillx-labs/bix3t7zl/evidence/dag-v4/benchmark-contract-measurements.json，不复制私有会话到仓库。
