End-to-end flow for the local simulated-Git-hosting E2E fixture: stage and commit all pending changes once with a fixed message, then create a simulated MR (POST /api/mrs), merge it (POST /api/mrs/{id}/merge, simulated fast-forward), read the merged state back through GET /api/mrs/{id}, and verify final local and simulated state. It enforces no remotes, fixture identity (optional), service targetHead equal to the pre-commit baseline, exactly one commit after baseline, and mergedSha == sourceSha. Only simulated hosting state changes; the local main branch is never moved and nothing is pushed. Requires git and curl on PATH; the service must be the loopback simulated hosting API documented in API.md. The fixture must be in its pre-run (baseline) state; restore between runs is the caller's responsibility.
