# SkillX 编写约定

本文区分包规范与插件约定。规范性字段以[原始草案](reference/specification.md)为准；当前可执行范围以[实现映射](implementation-map.md)和[DSH 契约](contract.md)为准。以下建议不代表插件已实现通用 SkillX 包导入。

原始草案要求保留 `SKILL.md` 和 `skillx.yaml`。仅包含指南的包可以是 Guide-only；只有完整声明并由 Host 支持的执行接口，才能宣称可被工作流调用。

## 能力命名

- `SKILL.md` 文件头保留普通 Skill header，至少包含 `name` 和 `description`。
- 名称使用 kebab-case，例如 `commit-and-simulate-mr-merge`。
- 名称应表达业务能力，不写实现细节、模型名或临时任务编号。
- 同名能力发布新版本，不通过改名绕过版本冲突。
- 同名 SkillX 优先于普通 Skill，因此命名要避免和无关 Skill 冲突。

## 能力边界

一个 SkillX 应只覆盖一个稳定任务结构。判断标准是：输入不同，但步骤、工具集合、输出格式和验证方式基本一致。

适合做成 SkillX 的任务：

- 本地变更提交、创建模拟 MR、合并后回读核验。
- 固定系统的数据读取、转换、写回。
- 多个确定性工具串联，少数节点需要模型抽取或生成。
- 已经成功执行过，且有足够证据提取输入、输出和验证条件的任务。

不适合直接做成 SkillX 的任务：

- 目标、步骤和工具都不稳定的一次性探索任务。
- 需要用户临场判断且无法表达为输入或确认的任务。
- 成功依赖未记录的外部状态、口头约定或本地隐式配置。
- 需要绕过当前会话权限、凭据或审批边界的任务。

## 输入输出

- 输入必须是对象根 Schema。
- 输出必须能用当前 DSH JSON Schema 子集校验。
- 必填字段只保留真正影响执行的变量，不能把历史路径、测试 ID、临时分支名硬编码在程序里。
- 输出应返回业务结果和必要证据摘要，不返回冗长日志。
- 对可变外部状态的判断必须说明来源。历史成功只说明当时成立，不代表现在仍然成立。

## 权限与副作用

- SkillX 不主动扩大权限，只继承调用方当前会话、root call 和执行 token。
- 有副作用的操作必须使用 DSH 工具完成，并遵循宿主策略。
- 对文件、Git、网络、浏览器、审批、消息发送等操作，要在能力内容和验证说明中写清副作用边界。
- 权限不足、登录失效、审批拒绝、凭据缺失等问题归为外部阻塞，返回给调用方处理。

## 依赖与版本

- 依赖其他 SkillX 时，必须声明精确名称和版本。
- 执行时加载依赖闭包，并校验版本没有漂移。
- 已发布版本不可变。优化会生成新版本，历史执行仍绑定旧版本。
- 依赖内容不暴露给外层调用模型；只有插件运行时可以按版本锁加载。

## 提取和优化

- 提取必须基于完整会话证据，不能只凭聊天摘要生成能力。
- 多个来源会话用于优化时，生成 Agent 必须读取全部选中证据。
- 生成 Agent 只能读证据、读当前能力和提交候选，不能执行业务副作用。
- 优化只修改被选中的能力。证据不足时应复用当前版本或说明无法发布。

## 文档口径

- 面向用户和开发者的说明统一写“启用 skillx”。
- 可以在讲内部实现时说“编排流程”“执行程序”“能力依赖”；用户入口统一称为 SkillX。
- 测试 JSON 中保留历史字段名，不为口径统一改动机器可读原始数据。

## Header 与清单分工

`SKILL.md` 的 YAML frontmatter 必需 `name` 和 `description`；`name` 必须与清单 `metadata.name` 完全一致，description 建议一致。推荐附加 `license`、`compatibility` 和 `metadata.skillx.manifest` / `metadata.skillx.version`，见[示例 header](example/SKILL.md)。许可证必须真实，未确定时不要照抄 Apache-2.0。

`skillx.version` 是能力包版本，不是规范版本；`apiVersion` 放在清单里，原草案为 `skillx.dev/v1alpha1`。Schema、权限、副作用、依赖和执行入口属于清单，不应为了补齐 header 全部重复塞进 frontmatter。

有接口时，`spec.interfaces` 必须是以接口名为键的映射，`spec.defaultInterface` 指向已定义接口；指南使用 `spec.guide.entry: SKILL.md`。不要使用原草案未定义的 `spec.skill.instruction`、接口数组、`mode` 或 `executor` 代替这些结构。

指南建议写清目的、适用/不适用场景、输入输出、工具、失败处理、安全边界和示例。指南不能扩大清单权限。对当前 DSH 黑盒能力，内部步骤属于实现说明，不应要求外层调用方重复执行。
