# DSH 原生 SkillX / Workflow 插件

插件仅使用 DSH 原生 Agent、会话、工具和 Skill API，不连接或启动 SkillX 项目，不包含 Python 引擎、Pi 桥或开发服务器。已安装的 DSH 负责模型提供方、凭据、权限和会话记录。

## 安装

```sh
./scripts/install.sh
./scripts/start.sh --no-open
```

使用已安装的 `dsh`，默认接入 `web` profile、端口 3080。可设置 `DSH_BIN`、`DSH_PROFILE` 和 `DSH_SKILLX_PORT`；安装不会替换 DSH 版本或模型配置。已在运行的 DSH 应由其原启动方式重启。

## 使用与边界

- 左侧 SkillX 和工作流面板使用 DSH 原生 React 组件，每条能力可启用或关闭。
- 会话操作菜单的“总结工作流”创建一个真正的 DSH 原生 Agent，读取所选会话证据。没有自动总结监听。
- 提取 Agent 生成正文和元数据，通过插件专属提交工具提交候选；成功结束后才发布为插件自有版本文件。Codex 不代写业务工作流。
- 优化支持同时选择最多 8 条执行会话；新的 DSH Agent 先看逐步耗时、用量索引，再分页读取完整证据，并根据原版本完成优化。失败、取消或版本冲突不覆盖已发布内容。
- 调用方通过 DSH `skill` 工具只获取功能及输入/输出契约，再调用 `capability_run`。实现与依赖正文留在插件内部，由 DSH 原生 Agent 生成可执行定义，通过宿主 PTC 运行；可组合固定版本的能力和内部推理调用，不是 DSH 工作模式。
- 执行失败先分类：内部问题在同次调用内由原生 Agent 恢复，外部阻塞返回精简原因。输出必须通过契约验证；详细步骤、错误与用量保留在私有执行记录中。
- 前台 `timeoutMs` 覆盖执行与当前任务恢复；到期停止业务执行并保留证据。后台能力维护使用独立生命周期和预算，前台超时不会取消它：只分析记录，交由新的原生 Agent 优化定义，不继续或重放已超时的业务操作。后台任务持久记录状态与关联会话，失败不冒充已修复。
- 同名能力优先于普通 Skill。历史执行证据保留来源，不等于当前仓库或外部状态仍然成立；Agent 必须判断哪些验证结果可复用。
- 提取/优化沿用来源对话的模型配置；多来源以第一个来源为主对话并记录其 ID。执行中的推理、恢复与后台诊断沿用本次调用方的模型、推理档位及请求配置，不回落全局默认模型。后台优化再继承诊断会话配置。提供方和凭据仍由宿主管理，不复制密钥。

## 开发与验证

`npm test` 运行 `tests/` 下的原生插件测试。`npm pack --dry-run` 检查发布白名单。

- `src/`：原生 Agent、执行、恢复、存储与证据处理。
- `client/`：DSH 网页端插件入口。
- `tests/`：宿主集成与单元验证。
- `scripts/`：安装、启动与运行检查。
- `docs/`：架构和成本分析。
- `.local/`：仅本机保留的旧实现和运行资料；不入 Git、不发布、不参与加载。

目录分工参考 [dsh-market](https://github.com/dsh-market/dsh-market)。本插件使用原生 ESM JavaScript，无需编译或复制源码至构建目录。

配置 `enableCapabilities: false` 可以关闭模型侧能力发现，同时保留管理和手动提取界面。测试切换必须保留现有模型的 endpoint、名称和凭据引用。

成本复盘与本次去重说明见 [准备阶段成本分析](docs/preparation-cost-analysis.md)。
