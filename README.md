# DSH SkillX 插件

这个插件把 DSH 会话中的成功执行提取成可复用的 SkillX 能力。SkillX 保留 Skill 的“按需发现”方式，但把可重复任务固化为带输入输出 Schema、版本、依赖、执行记录和恢复机制的黑盒能力。

插件运行在 DSH 内，复用 DSH 的 Agent、会话、工具、Skill Provider、PTC 运行时、模型配置、凭据、权限和会话记录。

## SkillX 在 DSH 插件中的应用

典型路径是：先由 Agent 完成一次代表性任务，再从该会话提取 SkillX。后续类似任务启用 skillx 后，模型只需要发现能力、读取契约、填充输入并调用 `capability_run`；内部步骤由插件按已发布版本执行。

```text
成功会话
→ 证据快照
→ DSH 提取 Agent
→ 契约校验与版本发布
→ 模型通过 capability_run 调用
→ 输出校验、回执和恢复
```

SkillX 对普通 Skill 的改进：

| 维度 | 普通 Skill | SkillX |
|---|---|---|
| 使用方式 | 模型读取说明后自行规划 | 模型读取契约后调用黑盒能力 |
| 上下文成本 | 容易加载长文档和参考资料 | 只暴露名称、说明和 Schema |
| 稳定性 | 每次重新选择工具和步骤 | 固定已验证执行路径 |
| 输出质量 | 依赖模型自检 | 输出必须通过 Schema 校验 |
| 版本治理 | 说明和脚本容易漂移 | 不可变修订、版本锁和依赖闭包 |
| 失败处理 | 调用方继续排查 | 插件分类失败、前台恢复、后台维护 |

## 测试效果

三轮对照任务为本地 commit、创建模拟 MR、合并 MR、回读核验。

| 指标 | 未启用 skillx | 启用 skillx | 变化 |
|---|---:|---:|---:|
| 平均耗时 | 74.583 秒 | 51.381 秒 | 减少 31.11% |
| 平均会话 Token | 244,280 | 139,644 | 减少 42.83% |
| 平均模型调用 | 10.333 次 | 6.333 次 | 减少 38.71% |

完整测试归档见 [docs/tests/2026-10-14](docs/tests/2026-10-14/README.md)。这组结果是小样本描述性对照，适合说明固定、多工具、可验证任务启用 skillx 后的收益来源。

## 安装

```sh
git clone https://github.com/zaoweiceng/dsh-skillx-workflow.git
cd dsh-skillx-workflow
./scripts/install.sh
./scripts/start.sh --no-open
```

使用已安装的 `dsh`，默认接入 `web` profile、端口 3080。可设置 `DSH_BIN`、`DSH_PROFILE` 和 `DSH_SKILLX_PORT`。已在运行的 DSH 应由其原启动方式重启。

## 使用与边界

- 左侧 SkillX 管理面板使用 DSH React 组件，每条能力可启用或关闭。
- 会话操作菜单可从所选会话提取 SkillX；插件会创建 DSH Agent 读取证据。
- 提取 Agent 生成正文和元数据，通过插件专属提交工具提交候选；成功结束后发布为插件自有版本文件。
- 优化支持同时选择最多 8 条执行会话；新的 DSH Agent 先看逐步耗时、用量索引，再分页读取完整证据，并根据原版本完成优化。失败、取消或版本冲突不覆盖已发布内容。
- 调用方通过 DSH `skill` 工具获取功能及输入/输出契约，再调用 `capability_run`。实现与依赖正文留在插件内部，由 DSH Agent 生成可执行定义，通过宿主 PTC 运行；可组合固定版本的能力和内部推理调用。
- 执行失败先分类：内部问题在同次调用内由 DSH Agent 恢复，外部阻塞返回精简原因。输出必须通过契约验证；详细步骤、错误与用量保留在私有执行记录中。
- 前台 `timeoutMs` 覆盖执行与当前任务恢复；到期停止业务执行并保留证据。后台能力维护使用独立生命周期和预算，基于记录诊断并交由新的 DSH Agent 优化定义。后台任务持久记录状态与关联会话。
- 同名能力优先于普通 Skill。历史执行证据保留来源，不等于当前仓库或外部状态仍然成立；Agent 必须判断哪些验证结果可复用。
- 提取/优化沿用来源对话的模型配置；多来源以第一个来源为主对话并记录其 ID。执行中的推理、恢复与后台诊断沿用本次调用方的模型、推理档位及请求配置，不回落全局默认模型。后台优化再继承诊断会话配置。提供方和凭据仍由宿主管理，不复制密钥。

## 开发与验证

`npm test` 运行 `tests/` 下的插件测试。`npm pack --dry-run` 检查发布白名单。

- `src/`：Agent、执行、恢复、存储与证据处理。
- `client/`：DSH 网页端插件入口。
- `tests/`：宿主集成与单元验证。
- `scripts/`：安装、启动与运行检查。
- `docs/`：SkillX 概念、契约、插件设计、运行机制和测试归档。

配置 `enableCapabilities: false` 可以关闭模型侧能力发现，同时保留管理和手动提取界面。测试切换必须保留现有模型的 endpoint、名称和凭据引用。

架构、能力契约、执行恢复与开发说明见 [文档索引](docs/README.md)。

### SkillX 工作台与监控

侧边栏统一为 **SkillX**，工作台内提供 **SkillX / 工作流 / 监控面板 / 执行记录** 四个选项卡。执行记录独立位于监控面板之后。内容默认居中，监控卡片根据可用宽度自动切换双列或单列。原工作流面板 ID 保留，兼容已保存的导航状态。

监控提供 Token 节省估算、任务成功/失败率、SkillX/Workflow 调用量、耗时与失败原因排行，以及执行原始记录。各卡片独立支持最近 1/3/7 天或自定义日期（包含截止日），Token 另支持 1/3/12 小时。记录分页展示并对敏感字段脱敏，可打开关联 DSH 会话。

统计范围是插件原生顶层能力执行与学习任务，按创建时间计入；取消和未结束任务不进入成功/失败率分母。恢复成功的执行使用 `resolved.json` 的最终回执，不重复计数。调用量不含内部依赖调用；Token 节省按每次成功复用的“原始提取会话平均用量 − 执行用量”求和，假设任务规模相当。基线追溯执行版本的最初提取证据；旧数据使用截至提取时刻的原始会话用量。只纳入原始用量与执行用量完整的对比，缺失时显示排除数，不把未知当作零；确认没有模型调用的已完成程序计为零执行 Token。推理与前台恢复的会话用量去重扣除；不含调用方对话、提取和独立后台维护成本，负值保留。没有结束回执的历史执行显示“未结束”，不推断仍在运行。

升级后重启 DSH 并刷新页面，以加载新增的监控 API。

能力详情页以执行为主：隐藏列表搜索，按输入契约生成字段（支持对象、数组、枚举及 JSON 输入），执行结果与取消操作在执行记录中展示。执行创建普通 DSH 会话，通过原生工具分发与权限链调用 `capability_run`，不通过模型重写参数；提交锁定所选版本，并使用请求幂等键避免网络重试重复执行。需要处理原生授权时，可从“查看执行会话”进入。

旧的纯文档能力可点击“生成执行接口”，系统自动使用原始提取证据交给原生能力作者编译，不再要求用户填写执行对话 ID。工作流展示程序中已命名的顺序阶段图；分支和循环位于阶段内部，未定义阶段的程序按单个执行单元展示，不将其宣称为完整控制流图。

监控卡片默认只保留关键摘要；完整口径放在折叠的“统计说明”中，缺失样本提示仅在存在缺失时展示。

SkillX 和工作流的列表、详情均支持删除。被其他现存能力引用时拒绝删除并显示引用者（停用条目也参与检查）；删除当前目录项后保留历史执行审计。并发操作按不可变修订 ID 校验，避免同名重建与旧版本混淆。

提取只提供冻结 JSONL 的引用，通过有界工具按需读取证据。流程依次规划职责、独立冻结验收契约、实现并根据失败回执修订；缺少复用价值或无法验证的内容允许跳过。预算按证据行数、字节数和阶段数计算，默认没有步数上限。验收使用隔离模拟工具，不执行历史业务命令；通过模拟验收不代表已经证明真实外部系统的行为。详见 [操作说明](docs/operation.md)。
